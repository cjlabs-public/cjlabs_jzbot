# TG Bot 代码架构

当前模块围绕 Telegram `Update` 分层：

```text
LongPollingTelegramBot
  -> UpdateRouter
      -> CommandRouter
      -> CallbackRouter
      -> MessageRouter
      -> EventRouter
      -> BotMembershipHandler
      -> IdShareMessageHandler
```

## 职责边界

`bot` 负责 bot 生命周期和 Telegram 长轮询接入。

`command/UpdateRouter` 是最外层路由，按 Update 类型决定下一跳。

`command/CommandRouter` 只处理斜杠命令。命令实现统一实现 `BotCommand`，由 `BotCommandRegistry` 自动注册。

`callback/CallbackRouter` 只处理 `callback_query`。按钮回调实现 `CallbackHandler`，通过 `callback_data` 前缀匹配。

`command/MessageRouter` 只处理普通消息。私聊、群聊、频道消息分别转给 `callback/message/privatechat`、`callback/message/group`、`callback/message/channel` 下的处理器。

`callback/message/share` 处理 Telegram 特殊分享消息，例如 `user_shared` 和 `chat_shared`。

`command/EventRouter` 处理非消息类事件，例如入群申请和成员状态变化。

`callback/event/BotMembershipHandler` 处理 bot 自身的 `my_chat_member` 事件，例如 bot 被拉入群、被移除或权限变化。

`common/enums` 放通用枚举，`service` 放业务能力，`util` 放 Telegram 消息、按钮、格式化和校验工具。

## message、callback、event 的区别

### message：用户发了一条消息

`message` 是用户真实发送到聊天里的内容。

例子：

```text
用户私聊 bot：你好
用户在群里发：今天活动几点开始？
频道发了一条 channel post
用户通过 Telegram 分享按钮发来 user_shared / chat_shared
```

普通消息路由：

```text
UpdateRouter
  -> MessageRouter
      -> PrivateMessageHandler
      -> GroupMessageHandler
      -> ChannelMessageHandler
```

特殊分享消息路由：

```text
UpdateRouter
  -> IdShareMessageHandler
```

注意：`/start`、`/help` 这类斜杠命令虽然也是从 `message` 里来的，但会先被 `UpdateRouter` 判断为命令，然后转给 `CommandRouter`，不会走普通消息处理器。

### callback：用户点了 bot 消息里的按钮

`callback` 不是用户发文字，而是用户点击 inline keyboard 按钮。Telegram 会把按钮上的 `callback_data` 发给 bot。

例子：bot 发了一条消息：

```text
请选择操作：
[获取我的用户ID]
```

按钮背后的数据是：

```text
cmd:getuserid
```

用户点击按钮后，群里不会新增一条 `cmd:getuserid` 消息，而是 Telegram 发来 `callback_query`。

按钮回调路由：

```text
UpdateRouter
  -> CallbackRouter
      -> GetUserIdCallbackHandler
```

`callback` 适合处理确认、分页、选择、开关设置、获取 ID 等按钮点击动作。

### event：聊天状态发生了变化

`event` 不是用户发消息，也不是用户点按钮，而是 Telegram 主动通知 bot 某个状态变化了。

例子：

```text
有人申请加入群
有人加入群
有人离开群
bot 被拉进群
bot 被踢出群
bot 从普通成员变成管理员
```

普通成员事件路由：

```text
UpdateRouter
  -> EventRouter
```

bot 自身成员状态变化比较特殊，会先走 `BotMembershipHandler`：

```text
UpdateRouter
  -> BotMembershipHandler
  -> EventRouter
```

### 一个完整场景

```text
用户发 /start
=> command，不是普通 message 处理

bot 回复：欢迎，请点击按钮
[获取我的用户ID]

用户点击按钮
=> callback，走 GetUserIdCallbackHandler

另一个用户加入群
=> event，走 EventRouter

这个新用户在群里说“大家好”
=> message，走 GroupMessageHandler
```

## 路由规则

```text
UpdateRouter.route(update, bot)
  hasMessage()
    userShared      -> IdShareMessageHandler.handleUserShared(update, bot)
    chatShared      -> IdShareMessageHandler.handleChatShared(update, bot)
    isCommand       -> CommandRouter.route(update, bot)
    other message   -> MessageRouter.route(update, bot)

  hasCallbackQuery  -> CallbackRouter.route(update, bot.getTelegramClient())
  hasMyChatMember   -> BotMembershipHandler.handle(update, client)
                     -> EventRouter.routeChatMemberUpdate(update)
  hasChatMember     -> EventRouter.routeChatMemberUpdate(update)
  hasChatJoinRequest -> EventRouter.routeJoinRequest(update)
```

## 新增功能放置建议

- 新增 `/xxx` 命令：放在 `command` 的合适子包中，实现 `BotCommand`。
- 新增按钮回调：放在 `callback` 的合适子包中，实现 `CallbackHandler` 或继承 `AbstractCallbackHandler`。
- 新增普通消息逻辑：按聊天类型放入 `callback/message/privatechat`、`callback/message/group` 或 `callback/message/channel`。
- 新增 Telegram 事件逻辑：优先放入 `command/EventRouter`；如果是 bot 自身成员状态事件，放入 `callback/event/BotMembershipHandler`。
